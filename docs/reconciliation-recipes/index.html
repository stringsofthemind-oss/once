RECONCILIATION RECIPES

When a write becomes ambiguous, ask what the provider can actually prove.

Retry safety depends less on the timeout itself than on the provider contract available after it.

Decision rule: never promote uncertainty to ABSENT merely because a response was lost or a local record is missing. Use the strongest available provider evidence; otherwise preserve UNKNOWN.

1. Provider-native idempotency key

Bind the provider idempotency key to the same stable logical operation identity used by Once. A retry of the same logical action reuses that key and the same effect-bearing request. If the provider rejects changed parameters under the same key, treat that as a conflict rather than inventing a fresh operation.

2. Authoritative readback by provider object ID

If the first response exposed a durable provider object ID, persist it as soon as it is trustworthy. After uncertainty, retrieve that exact object and map the provider state to CONFIRMED, ABSENT only when the provider contract truly establishes absence, or UNKNOWN.

3. Lookup by stable business or request identity

If the direct object ID was lost but the provider supports lookup by a stable request key, external reference, metadata field, or business identity, reconcile against that key. Reject multiple incompatible matches instead of selecting the newest candidate.

4. Eventual consistency

A temporarily empty read is not necessarily proof that nothing happened. Keep UNKNOWN through the documented visibility window, retry bounded reads, and only transition to ABSENT when the provider semantics make absence authoritative enough for another protected write.

5. No authoritative lookup

If the provider offers neither safe idempotency nor a trustworthy read path, Once cannot manufacture certainty. Preserve UNKNOWN, block automatic replay, and require an operator or a provider-specific recovery procedure.

6. Definitive pre-dispatch failure

Failures that provably occur before the provider can begin the side effect can be classified differently from post-dispatch transport loss. The burden of proof belongs on the ABSENT transition.

Important: reconciliation quality is provider-specific. A 404, missing local row, timeout, or process crash is not automatically authoritative evidence of ABSENT.
